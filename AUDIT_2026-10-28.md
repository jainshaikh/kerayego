# KerayeGo Audit — 2026-10-28

Audit of the KerayeGo Partner work (backend branch `feat/team-and-drivers`, `kerayego-partner`,
`kerayego-web` changes) against `PROVIDER_APP_PLAN.md`, plus what it broke in the unchanged customer app.
Six independent reviewers read the code on both sides of every contract.

**How to use this file:** it's the work list for after the audit. Tick an item when it's done and add a
dated line to the Changelog at the bottom. "A12", "D16" refer to `PROVIDER_APP_PLAN.md`. Items fixed
during the audit itself are listed in "Fixed during the audit" with a ✅ and are not repeated below.

**Headline:** the plan says "Complete. All planned phases implemented and verified". That isn't true
yet. A lot is built and the API contracts the partner app calls match the backend, but **drivers and
managers can't use the partner app at all**, account deletion doesn't run or delete enough, several
plan decisions have no data model, and the customer app breaks on the new backend. Update the plan's
status line once the P0 items below are done.

- ✅ New specs: booking-requests service, driver jobs, auth service, vehicles service; extended admin,

## P0 — must fix before anyone uses this (blocks the core flows)

- [x] **Drivers can't accept an invite**: `useAcceptBusinessInvite` / `useLeaveBusiness` exist but no
  screen uses them. Add a "My businesses / invitations" screen with Accept, Decline and Leave (A38).
- [x] **Business can't assign a driver when accepting a booking**: no driver picker on Accept
  (`bookings/[id].tsx`, `StatusActionSheet.tsx`). Build the picker from the team list (ACTIVE + DRIVER
  + VERIFIED + valid licence); show "busy at that time".
- [x] **Backend: a dedicated "assign / re-assign driver" endpoint** that always validates (membership,
  verified, licence valid through the booking end, no overlapping job — checked inside the transaction
  or with a per-driver lock, including the driver's own carpool trips). Today re-assigning after a
  driver declines is impossible.
- [x] **No way for a driver to become VERIFIED**: no driver CNIC/licence/photo upload, no admin review
  screen or endpoint; nothing ever sets `verificationStatus = VERIFIED` (A12). Until this exists no
  driver can be assigned.

- [x] **Deletion leaves personal data**: personal cars + images, `UploadedDocument` rows and their S3

  the background job.
- [x] **Requesting deletion doesn't sign the person out**: revoke all refresh tokens, block new
  bookings/trips/seat requests while `PENDING_DELETION`, re-run the "anything active?" checks when the
  job runs (skip and notify if active).
- [x] **Customer app (`kerayego-mobile`) has no "Delete account"** — Apple 5.1.1(v) and Google Play
  require it; Google also needs a web page for deletion requests (`kerayego-web` has none). Add a

- [x] Partner app: move "Delete account" from the business profile to an account screen every role
  can reach; add the optional "Why are you leaving?" field (A51).
- [x] Confirmation email with a "Cancel deletion" link (A51); alert businesses when a driver is removed
  by deletion; tell managers/drivers when a business is deleted. (Email existed; the pushes `team.memberDeleted`
  and `business.closed` added 2026-11-01.)
- [x] Decide: login auto-cancels deletion **before** the partner gate — a customer with a pending
